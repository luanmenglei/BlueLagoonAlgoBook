# 维护约定

标题固定为 **BlueLagooon常见题目模式字典+图灵奖速查表**。本册面向赛时封闭纸质资料；正文必须独立可读，外部题号、题面和题解链接只放来源记录或网页来源折叠栏。

## 条目怎么写

每条给 3–5 个短检索词，可用口语和常见同义说法。检索入口可以宽泛，正文不能宽泛；不得把众数与多数、极大与最大等不同模型合并成同义词。

正文依次交代：**对象是什么、求什么或改什么、有什么限制、能用什么方法及复杂度**。需要时明确：

- 图的方向、权值、路径是否简单，点不交还是边不交。
- 静态还是动态，在线还是离线，预处理、单次操作、总时间与空间。
- 判存在、求最优、精确计数还是模计数；对象是否有标号、顺序是否区分、同一结果是否重复计算。
- 一般模型与可解特例的边界，公式的零值、空对象、越界及退化情形。

`highlights` 只取正文原样短语，优先突出必要前提、核心转化和容易混淆的区别；避免整段加粗。一次只讲清一个模型，较长证明和公式放 `derivation`，但适用条件必须留在正文。

## 计数先讲组合含义

保持两层组织：先在“先判断能不能数”中区分一般困难模型与可利用的结构，并维护可行性速览；再在“组合计数与多项式模式”中讲可复用的具体做法。六类格路、反射、卡特兰、球盒与嵌套集合模型作为直观入口。

先说明数的是什么，再给组合转化或直观公式，最后解释数组如何构造、相乘、取系数及乘回阶乘。**不要机械堆生成函数、GF、Log／Exp 名词**，不能用“套多项式”代替操作步骤；确需生成函数时，说明每个因子、系数和标号约定的含义。

例如，嵌套集合的连乘必须写明集合真正包含，不能只写“按大小排序”；格路反射必须交代允许贴边还是严格不越界；整数划分与可区分元素分组不能混用。

## 复杂度与核验

按赛场常用精确实现描述，不展开理论猜想史。分清输入规模、数值大小、摊还、期望、压位和机器字操作；`n polylog n` 不能缩成 `polylog`。

- “摘要不能相减／合并”不等于问题困难；“常用分治”不等于必须分治。
- 记录经过核对的实现上界，不自动称为已证最优复杂度；一般困难结论必须写清模型。
- 多项式加速写明模数、阶乘及积分分母可逆、NTT 长度等条件；模计数为零不能直接当作无方案。
- 没有实测时，不断言某实现普遍更快；说明压位、常数、值域等取舍。
- 新公式、关键转化和困难性边界核对可靠来源，必要时用小规模枚举验证；来源和验证范围留在 `research/`。

## 编号、索引与生成

保持 **M → D → N → C → Q → I**，信息论在最后。已有条目编号不因改名或重排而改变；新增条目使用新编号，呈现次序由分组决定。

内容只在 `source/entries.json` 维护。新增或修改条目时，同步关键词、题面索引、计数分组、速览、来源和交叉引用；检查索引编号存在，搜索能找回条目。`source/tables.tex` 与 `source/tables.md` 由 `print_tables` 自动生成，不手改生成文件。

重建并同步 Markdown、TeX、PDF、HTML 和研究记录；检查加粗片段、目录与页码、公式显示、边界条件、分类搜索及打印溢出。仅在本目录维护，不自动并入主书章节。
